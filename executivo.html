Regras de Negócio e Funcionalidades Core

Rateio Automático por CPF

O core financeiro avalia o cpf_destinatario de toda Nota Fiscal inserida. Se corresponder a um sócio cadastrado, a despesa é integralmente atribuída a ele. Notas sem CPF de sócio entram no funil Pendente de Revisão para atribuição manual no Dashboard.

Conciliação Bancária

Módulo preparado para processamento de extratos. Transações são cruzadas com Aportes e Notas Fiscais usando match de Valor + Data (tolerância de 3 dias configurada). Registros órfãos ficam aguardando pareamento humano.

Workers Assíncronos & OCR

Operações pesadas não bloqueiam a interface. O upload de notas via WhatsApp ou Web é enviado para uma fila Redis/BullMQ. O processamento (leitura de QR Code ou envio ao webhook do n8n para OCR) roda em background, devolvendo o resultado via API de webhooks e emitindo Alertas.

Dashboard de Sócios (Lado a Lado)

Visão gerencial desenhada para dupla de sócios: acompanhamento simétrico de Aportes vs. Despesas Alocadas, gerando o saldo devedor ou credor de cada um em tempo real em relação ao orçamento global (valor_orcado).

Stack Tecnológica

  • Frontend: Next.js (App Router), React 18, Tailwind CSS. Build standalone Dockerizado para otimização de imagem.
  • Backend (API & Worker): Node.js, Express, TypeScript. Dividido em dois entrypoints lógicos (Server HTTP e Consumidor BullMQ) usando a mesma base de código.
  • Banco de Dados: PostgreSQL gerenciado através do Prisma ORM (Tipagem estática e migrações seguras).
  • Mensageria: Redis operando como broker em memória para as filas de jobs gerenciadas pelo BullMQ.
  • Infra/Routing: Docker Compose orquestrando as redes. O proxy Traefik (pré-existente na sua VPS de laboratório) resolve os certificados Let's Encrypt e direciona as requisições para os containers.

Modelo de Segurança

A autenticação emprega JWT transmitido via cookies httpOnly. Esse padrão impede que scripts maliciosos injetados no navegador (XSS) roubem a credencial de sessão.

Guia de Implantação na VPS Ubuntu

Com a stack configurada, estes são os passos de subida no seu ambiente Docker hosteado:

  1. Transferência e Preparação: Suba o repositório na sua instância.
  2. Configuração do Environment: 
    cp .env.example .env
nano .env # Ajuste as senhas (POSTGRES_PASSWORD, JWT_SECRET, CREDENCIAIS ADMIN)
  3. Build e Subida dos Serviços: 
    docker compose build
docker compose up -d
  4. Migração de Banco e Seed Inicial: Rode os comandos abaixo de fora para instruir o container da API a formatar o Postgres e gerar o Admin: 
    docker exec -it obra_api npm run prisma:migrate
docker exec -it obra_api npm run seed
  5. Validação de Rotas Seguras: Confirme as rotas nos terminais web acessando https://obra.iastudio.shop (Frontend) e https://api.iastudio.shop/health (Status Backend).
