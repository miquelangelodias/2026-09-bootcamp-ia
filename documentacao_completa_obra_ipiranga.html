Sistema de gestão financeira

Obra Ipiranga 1 — documentação técnica e operacional

Objetivo

Substituir o controle em planilha da obra por um sistema web próprio, mantendo as mesmas regras de rateio e categorização, com dashboards, captura automática de notas fiscais, alertas em tempo real e conciliação bancária.

Stack

Backend

Node.js + Express + TS

ORM / Banco

Prisma + PostgreSQL

Filas

Redis + BullMQ

Frontend

Next.js + Tailwind

Integrações

n8n (OCR e WhatsApp)

Deploy

Docker Compose + Traefik

Fases entregues

Fase 1Docker Compose, schema Prisma, seed do admin.
Fase 2Setup do Express, autenticação JWT, schemas Zod.
Fase 3CRUD de notas fiscais, aportes, sócios e categorias, com rateio por CPF.
Fase 4Webhooks WhatsApp/Sheets via n8n, conciliação bancária, exportação CSV.
Fase 5Frontend Next.js: login, 4 dashboards, tabela com filtros, cadastros.

Rateio de despesas

  • O CPF do destinatário na NF-e é comparado aos sócios cadastrados.
  • Bateu com um sócio: despesa 100% dele, status confirmada.
  • Não bateu: nota fica pendente, sem sócio, para atribuição manual.

Notas fiscais e categorização

  • Identificadas pela chave de acesso de 44 dígitos, sem duplicidade.
  • Categoria automática por fornecedor; sem match, fica sem categoria até edição manual.
  • Todo campo de toda entrada é editável e removível pela interface.

Aportes e conciliação

  • Saldo em caixa = total aportado menos total gasto.
  • Extrato bancário importado é comparado por valor exato e data, com tolerância de 3 dias.
  • Sem correspondência, a transação fica pendente na lista de divergências.

Acesso e alertas

  • Acesso fechado por login; papéis admin e sócio.
  • Toda inserção nova (site, WhatsApp, OCR ou planilha) dispara um alerta via fila.
  • Novo sócio cadastrado passa a ser reconhecido automaticamente no rateio por CPF.

Passo a passo para colocar no ar

  1. Rodar, em ordem, os scripts setup-fase1.sh a setup-fase5.sh na pasta do projeto.
  2. Copiar .env.example para .env e preencher com senhas, segredos JWT e credenciais reais.
  3. Dentro de api/: npm install, depois npm run prisma:generate e npx prisma migrate dev --name init.
  4. Rodar npm run prisma:seed para criar o usuário administrador inicial.
  5. Dentro de web/: npm install e testar com npm run dev localmente antes do deploy.
  6. Configurar o fluxo no n8n com os webhooks de OCR e envio de WhatsApp, apontando para N8N_WEBHOOK_URL.
  7. Instalar o Apps Script na planilha Google Sheets e configurar o gatilho instalável de edição, apontando para /webhooks/sheets.
  8. No VPS: ajustar o nome da rede traefik_proxy no docker-compose.yml conforme o Traefik já existente, depois docker compose up -d --build.
  9. Confirmar DNS de api.iastudio.shop e obra.iastudio.shop apontando para o VPS.
  10. Fazer login pela primeira vez com o e-mail e senha definidos em SEED_ADMIN_EMAIL/SEED_ADMIN_PASSWORD.

Login

Acesse obra.iastudio.shop, entre com e-mail e senha. A sessão fica em um cookie válido por 7 dias.

Dashboards

O menu lateral tem quatro visões: por sócio (Elismar e Miquelangelo lado a lado), visão geral (orçado x realizado x saldo), por categoria e por período (gráfico mensal de gastos e aportes).

Tabela de dados

Em "Tabela de dados", filtre por sócio, categoria ou status. Categoria e sócio de cada nota são editáveis direto na linha, sem precisar abrir outra tela.

Cadastros

Em "Cadastros", adicione ou remova sócios e categorias. Um sócio novo já passa a ser reconhecido nas próximas notas pelo CPF.

Rotina semanal sugerida

Revisar as notas com status pendente na tabela de dados, conferir alertas recebidos no WhatsApp, e uma vez por mês importar o extrato bancário em "Conciliação" para revisar divergências.

docker-compose.yml

services:
  postgres:
    image: postgres:16-alpine
    restart: unless-stopped
    environment:
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: ${POSTGRES_DB}
    volumes:
      - postgres_data:/var/lib/postgresql/data
    networks: [internal]

  redis:
    image: redis:7-alpine
    restart: unless-stopped
    volumes: [redis_data:/data]
    networks: [internal]

  api:
    build: ./api
    restart: unless-stopped
    command: ["node", "dist/server.js"]
    depends_on: [postgres, redis]
    env_file: .env
    networks: [internal, traefik_proxy]
    labels:
      - traefik.enable=true
      - traefik.http.routers.obra-api.rule=Host(`api.iastudio.shop`)
      - traefik.http.routers.obra-api.entrypoints=websecure
      - traefik.http.routers.obra-api.tls.certresolver=letsencrypt
      - traefik.http.services.obra-api.loadbalancer.server.port=3000

  worker:
    build: ./api
    restart: unless-stopped
    command: ["node", "dist/worker.js"]
    depends_on: [postgres, redis]
    env_file: .env
    networks: [internal]

  web:
    build: ./web
    restart: unless-stopped
    depends_on: [api]
    env_file: .env
    networks: [internal, traefik_proxy]
    labels:
      - traefik.enable=true
      - traefik.http.routers.obra-web.rule=Host(`obra.iastudio.shop`)
      - traefik.http.routers.obra-web.entrypoints=websecure
      - traefik.http.routers.obra-web.tls.certresolver=letsencrypt
      - traefik.http.services.obra-web.loadbalancer.server.port=3000
